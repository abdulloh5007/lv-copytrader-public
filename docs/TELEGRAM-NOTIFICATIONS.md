# Telegram-уведомления LV Copytrader


## Что связано с настройками

- `ui.locale` — русский или английский язык карточек.
- `notifier.enabled`, `notifier.types` — существующие переключатели доставки: входы, изменения, закрытия, отказы, предупреждения. TP/SL остаются в категории закрытий, б/у — изменений. При TP и автоматическом б/у состояние остатка включается в карточку закрытия.
- `notifier.admin_ids` и привязанный чат — прежние ограничения доступа.
- `trading.ladder_volume` — карточка показывает реально открытые объёмы частей; объём не подменяется размером из текста сигнала.
- `trading.be_after_tp1`, `runner_mode`, `LADDER_BE_BUFFER_POINTS` — прежние правила сопровождения. Карточка читает итоговый SL после выполнения этих правил.
- `SL_WATCHDOG_SECONDS` — частота проверки исчезнувших позиций и истории TP/SL. По умолчанию 60 секунд; уведомление появляется после очередной проверки, а не через поток тиков.

## Формат и группировка

Основной способ доставки — настоящий `sendRichMessage` с `rich_message.html`: заголовок и компактные абзацы. При явном отказе в поддержке метода/формата используется прежний HTML `sendMessage`. Таймаут не запускает отправку вторым методом: применяется обычная политика повторов. Меню slash-команд сохраняется.

[Telegram Bot API: sendRichMessage](https://core.telegram.org/bots/api#sendrichmessage), [InputRichMessage](https://core.telegram.org/bots/api#inputrichmessage).

Один запуск обработки сигнала собирает входы по `signal_ref + symbol + side + order_type`. Несколько вызовов открытия в одном запуске дают одну карточку; разные сигналы, инструменты, направления и типы ордеров не смешиваются. Сбор заканчивается в `finally`, включая ошибку или отмену запуска. Отдельный вызов исполнителя без запуска отправляет одну карточку на весь план открытия. Перенастройка TP покрытия по фактической цене исполнения включена в итоговую карточку входа и не создаёт лишнее уведомление изменения.

В карточке указаны объёмы частей и их сумма, фактический вход, SL/TP каждой позиции и тикеты. При неполном исполнении показываются исполненный и запрошенный объёмы; неудавшиеся части дают отдельную ошибку. Лесенка помечена отдельно: покрытие 1R, runner, цели без ордеров и выбранная политика SL.

## Примеры содержания

Цены и тикеты ниже условные.

```text
🟢 ВХОД — BUY XAUUSD
Режим Обычный
Объём 0.20 + 0.20 = 0.40
1 · 2380.00 · SL 2370.00 · TP 2390.00
2 · 2380.00 · SL 2370.00 · TP 2400.00
После TP1 — остаток в б/у
Тикеты 500001, 500002
```

```text
✅ TP1 ЗАБРАН — BUY XAUUSD
Причина закрытия тейк-профит
Объём 0.20
Вход 2380.00
Цена закрытия 2390.00
Приб./убыток +200.00 USD · +1000 пт
Тикет 500001
500002 · в б/у · SL 2380.10
```

Если перенос отклонён, сначала приходит ошибка, а карточка TP показывает `SL сохранён` и фактический прежний SL. При выключенном автоматическом б/у успешный перенос не обещается. Для покрытия лесенки заголовок — `TP ПОКРЫТИЯ · 1R`, поскольку это не обязательно TP1 из канала. Для runner используется сохранённый индекс выбранной цели.

Дополнительные статусы: `ОРДЕР ВЫСТАВЛЕН`, `ЧАСТИЧНЫЙ ВХОД`, `ИЗМЕНЕНО`, `БЕЗУБЫТОК`, `СТОП-ЛОСС`, `ЗАКРЫТО`, `ОРДЕР ОТМЕНЁН`, `ОШИБКА`, `ВНИМАНИЕ`.

## Проверки

`backend/tests/test_notification_cards.py` проверяет нативный API и fallback, две позиции в одной карточке, разделение сигналов, обычный/отложенный/частичный вход и лесенку, статусы закрытия, TP1 с включённым и выключенным б/у, отказ брокера, задержку истории, отказ до отправки ордера и многострочную HTML-разметку. Внешний Telegram и реальные сделки в тестах не используются.
