# LVCT — установка и терминальная панель

`lvct` устанавливает и обслуживает отдельную копию LV Copytrader. Python CLI работает
на Linux, Windows и macOS; для торгового runtime нужен Docker с Linux-контейнерами.
CLI не содержит сторонних Python-зависимостей. Flask, Node, Wine и MT5 на хост отдельно
ставить не нужно: приложение и торговый терминал собираются внутри Docker.

## Совместимость

**Текущий статус:** кроссплатформенная установка команды `lvct` и локальный запуск
всего торгового проекта — разные уровни поддержки. На Apple Silicon автоматический
локальный runtime пока не реализован и не испытан. Для Windows/Intel Mac описан путь
через Docker Desktop, но полноценная проверка MT5 на этих desktop-системах ещё нужна.
Зелёные unit-тесты CLI не являются результатом проверки MT5 на реальном Mac.


| Компьютер | CLI | Торговый runtime |
| --- | --- | --- |
| Linux x86-64 | Да, Python 3.10+ | Локальный Docker Engine + Compose 2.24+ |
| Windows x86-64 | Да, PowerShell / Windows Terminal | Docker Desktop с Linux-контейнерами / WSL 2 |
| Intel Mac | Да, Terminal | Docker Desktop с Linux-контейнерами |
| Apple Silicon Mac / Windows ARM | Да | Linux x86-64 сервер через Docker SSH context |
| Linux ARM64 | Да | Проверенный FEX/Wine путь описан в [ARM64 guide](../deploy/arm64/README.md); новый CLI не автоматизирует этот специальный runtime |

Поддержка CLI не равна проверке брокерской сделки на каждой ОС. Локальный запуск
Wine/MT5 на Docker Desktop требует отдельной проверки. Локальная эмуляция MT5 на
Apple Silicon в этот установщик не включена: `doctor` откажет до запуска контейнеров
и предложит SSH-режим. Существующая ARM64-установка проекта продолжает использовать
свои файлы и контейнеры.

Для Docker Desktop ориентируйтесь на актуальные требования
[Windows](https://docs.docker.com/desktop/setup/install/windows-install/) и
[macOS](https://docs.docker.com/desktop/setup/install/mac-install/).
Для сборок и Wine желательно выделить Docker не меньше 4 GiB, для рабочего компьютера
разумно иметь 8 GiB RAM и больше. CLI предупреждает о небольшом выделенном объёме памяти.

## Установка из текущего checkout

Эти команды работают с исходниками, в которых уже есть `cli/` и установщики:

```sh
sh install.sh --source "$PWD"
```

В Windows из корня проекта:

```powershell
.\install.ps1 -Source $PWD
```

После установки команда попадает в `~/.local/bin/lvct` на Linux/macOS или в пользовательский
каталог `%LOCALAPPDATA%\lvct\bin` на Windows. Установщик печатает точный путь. Если
`~/.local/bin` ещё нет в PATH, добавьте его в конфигурацию своей оболочки:

```sh
export PATH="$HOME/.local/bin:$PATH"
```

Windows-установщик добавляет только свой каталог в пользовательский PATH; откройте новый
терминал. Глобальная ExecutionPolicy не изменяется. Если политика вашей организации не
разрешает скрипты, используйте `python cli/bootstrap.py --source .` после установки Python.

## Официальная страница установки

Откройте [docs.lvenc.site](https://docs.lvenc.site/): сайт выберет ОС, покажет команду
и даст скопировать её. Там же есть инструкции на EN/RU/UZ. Preview-сборки могут быть
новее публичного GitHub: они имеют отдельный SHA-256 архив и пометку preview, без
перезаписи релизных тегов. Установщик сверяет размер и SHA-256 с HTTPS-манифестом;
это проверка целостности, а не отдельная цифровая подпись релиза.

```sh
curl -fsSL https://docs.lvenc.site/install.sh | sh -s -- --install-python
```

Windows PowerShell:

```powershell
curl.exe -fsSL https://docs.lvenc.site/install.ps1 | Out-String | iex
```

Официальный установщик предложит установить Python через WinGet, если Python 3.10+
ещё нет. `Out-String` собирает весь скрипт перед запуском, а `iex` запускает его в
PowerShell. Системная политика выполнения скриптов не меняется.

## Установка через GitHub / PowerShell

Эти URL должны содержать новую версию установщика в публичной ветке `main`. До публикации
изменений используйте установку из checkout выше. Старый опубликованный тег 0.1.0 может
не содержать CLI.

Linux/macOS:

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/abdulloh5007/lv-copytrader-public/main/install.sh | sh
```

Если Python 3.10+ ещё нет, установщик умеет использовать apt на Debian/Ubuntu или уже
установленный Homebrew на macOS:

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/abdulloh5007/lv-copytrader-public/main/install.sh | sh -s -- --install-python
```

При отсутствии Homebrew на Mac установите Python с python.org и повторите первую команду.
Установщик не запускает отдельную установку Homebrew и не подменяет системный Python.

Windows PowerShell:

```powershell
& ([scriptblock]::Create((Invoke-RestMethod 'https://raw.githubusercontent.com/abdulloh5007/lv-copytrader-public/main/install.ps1'))) -InstallPython
```

`-InstallPython` использует WinGet только при отсутствии подходящего Python. Для проверки
скачайте файл и изучите его перед выполнением. Установщики не требуют аккаунта GitHub и
не принимают GitHub PAT.

Установщик получает публичную ветку/тег, разрешает её в конкретный commit SHA и скачивает
архив этого коммита по HTTPS. Архив проверяется на выход за каталог, симлинки, приватные
файлы, дубли путей и чрезмерный размер. Код CLI упакован в zipapp; pip и venv не нужны.
Это привязка к GitHub-коммиту, а не утверждение о подписи релиза отдельным ключом.

Для фиксации версии используйте `--ref COMMIT_OR_TAG`; она должна содержать CLI.
Повторная установка обновляет сам инструмент, сохраняет `installation.json`, `runtime.env`
и работающий source bundle существующего runtime. Запущенные контейнеры не заменяются.
Обновление runtime выполняется командой `update --apply` только во время явной остановки, см. ниже.

## Первый запуск

```sh
lvct --help
lvct deps
lvct deps --install
lvct init
lvct doctor
lvct start
lvct status
lvct open
```

`deps --install` сначала показывает конкретный способ установки и просит согласие:

- Linux: официальный Docker convenience installer с get.docker.com на новом хосте.
- macOS: `brew install --cask docker-desktop`, если Homebrew уже есть; иначе ссылка на
  официальный установщик Docker Desktop.
- Windows: WinGet package `Docker.DockerDesktop`.

Если Docker уже установлен, команда откажется его заменять. Сначала используйте `doctor`.
Первый запуск Docker Desktop, включение виртуализации/WSL, возможная перезагрузка ОС
и подтверждение условий Docker выполняются средствами самой ОС. CLI их не обходит.
Для производственного Linux также доступна ручная установка из
[официального репозитория Docker](https://docs.docker.com/engine/install/ubuntu/).
CLI не добавляет пользователя в привилегированную группу `docker` автоматически.

Мастер `init` спрашивает:

1. Имя и пароль администратора панели, пароль вводится скрыто и дважды.
2. Точное название сервера брокера, номер и пароль счёта MT5. Начинайте с demo.
3. При желании — Telegram API ID и hash. Их можно заполнить позже в панели.

Ключ шифрования и RPC-токен генерируются автоматически. Мастер не перезаписывает готовую
установку и не запускает контейнеры. Пароли с `$`, кавычками, пробелами и кириллицей
сохраняются без раскрытия переменных оболочки.

После `start` Wine и MT5 может понадобиться несколько минут. В Settings подключите Telegram,
выберите канал и AI-провайдера, настройте уведомления, проверьте счёт и торговые ограничения.
Сам `start` не включает торговлю; решение об arm принимается явно в панели. Если подключение
брокера требует начального выбора сервера, используйте существующее руководство проекта.

Команда `lvct` без аргументов открывает цветное меню в обычном терминале. В pipe/CI она
печатает справку. `NO_COLOR=1` или `lvct --no-color` отключают цвета.

## Команды

| Команда | Действие |
| --- | --- |
| `lvct init` / `lvct setup` | Мастер новой установки |
| `lvct doctor` | Проверка Docker, Compose, архитектуры и файлов; никаких торговых запросов |
| `lvct deps` | Обнаружение зависимостей и инструкция |
| `lvct deps --install` | Установка отсутствующего Docker с отдельным подтверждением |
| `lvct start` | Сборка при необходимости и запуск; работающие контейнеры не пересоздаются |
| `lvct start --build` | Явная сборка перед запуском остановленных сервисов |
| `lvct status` / `status --json` | Состояния контейнеров; не доказательство исполнения ордеров |
| `lvct logs --tail 100` | Логи с маскированием известных ключей и паролей |
| `lvct logs -f --service app` | Следить за логами приложения; Ctrl+C останавливает только просмотр |
| `lvct open --settings` | Открыть настройки; для SSH-контекста поднять локальный туннель |
| `lvct password` / `lvct passwd` | Сменить пароль панели без перезапуска торговли |
| `lvct password --username NAME` | Одновременно сменить имя администратора |
| `lvct config` | Пути и конфигурация со скрытыми секретами |
| `lvct stop` / `lvct restart` | Обслуживание с подтверждением паузы управления позициями |
| `lvct --version` | Версия инструмента |

`stop` и `restart` не закрывают брокерские позиции и не снимают SL/TP, но при паузе не
работает управление приложением. Эти команды спрашивают подтверждение; `--yes` означает
явное подтверждение этого действия. CLI не содержит команды отправки тестового ордера.

## Mac с M-чипом / удалённый runtime

Этот режим использует **ваш существующий Linux x64 компьютер или VPS**. Его адрес
и SSH-пользователя вы задаёте в `--remote user@server.example`. Аренда и настройка
сервера выполняются отдельно; оператору нужны собственный SSH-ключ и права Docker.
В комплект CLI не входит размещение брокерских аккаунтов на сервере разработчика.

Сам MetaTrader 5 официально доступен для Apple M1 и новее:
[инструкция MetaQuotes](https://www.metatrader5.com/en/terminal/help/start_advanced/install_mac).
Это не подтверждает работу нашей связки Python SDK, RPC и автоматического управления
терминалом на macOS. Текущий Ubuntu ARM/FEX runtime привязан к Linux-библиотекам хоста;
его нельзя напрямую объявить готовым runtime для Docker Desktop на Mac.

Для локального Apple Silicon варианта ещё требуются упаковка подходящего Wine/MT5
окружения, запуск Python/RPC в нём, приватное подключение backend и проверка установки,
IPC, чтения состояния и восстановления на реальном Mac. Проверки не должны отправлять
брокерские ордера, использовать рабочие сессии владельца или включать торговлю.


Нужен Linux x86-64 сервер с Docker Engine/Compose и уже настроенный доступ OpenSSH по ключу.
Пользователь SSH должен иметь доступ к Docker на этом сервере; на сервере нужен Python 3 для проверки свободного порта. На компьютере нужны
Docker CLI, Compose и OpenSSH; Docker Desktop — один из способов получить CLI и Compose.

```sh
lvct init --remote ubuntu@server.example
lvct doctor
lvct start
lvct status
lvct open
```

CLI создаёт собственный контекст и передаёт `docker --context NAME` при каждом действии.
Глобальный Docker context не переключается. Исходники передаются Docker для сборки по SSH;
сначала клонировать репозиторий на сервер вручную не требуется. Если контекст уже создан:

```sh
lvct init --context my-linux-server
```

Панель остаётся на loopback сервера. `lvct open` держит туннель
`127.0.0.1:PORT → SSH → 127.0.0.1:PORT` в текущем терминале и печатает адрес, который нужно
открыть браузером. Ctrl+C закрывает туннель, не останавливая сервер. Проверка SSH host key
остаётся включённой. Порт Docker TCP и RPC MT5 наружу не открываются.

Это новая независимая установка. CLI не подключает существующие приватные тома владельца
и не переносит торговую базу автоматически. Не настраивайте второй активный экземпляр
на тот же реальный счёт без осознанной миграции и остановки старого ingest.

## Пароль и хранение конфигурации

`lvct password` требует работающий контейнер приложения и локальные права Docker владельца.
Новый пароль передаётся внутрь через stdin, а не в командной строке. Backend сохраняет
солёный PBKDF2-SHA256 хеш с 600 000 итераций в `admin-credentials.json` внутри data volume.
Дорогая проверка хеша вынесена из торгового event loop в ограниченные worker-потоки;
переполнение возвращает 429 без очереди. Перезапуск не нужен. Предыдущие cookie перестают работать, открытые WebSocket-сессии
закрываются до следующего кадра. Новый override сохраняется после рестарта.

Значение `SP_AUTH_PASSWORD` в первоначальном `runtime.env` остаётся bootstrap-значением;
после смены пароля приоритет имеет data volume. Удалять override ради возврата старого
пароля не требуется: используйте `lvct password` повторно. До первого запуска используйте
пароль, который ввели в `init`.

По умолчанию состояние инструмента находится:

- Linux: `${XDG_DATA_HOME:-~/.local/share}/lvct`.
- macOS: `~/Library/Application Support/lvct`.
- Windows: `%LOCALAPPDATA%\lvct`.

`LVCT_HOME` или `lvct --home PATH ...` выбирают другую установку. Пароль, ключ шифрования
и RPC-токен лежат в `runtime.env`, настройки проекта — в `installation.json`.
На Unix секретные файлы имеют режим 0600; на Windows каталог находится в профиле
пользователя и использует его ACL. `init` создаёт случайное имя Compose-проекта и отдельные
тома data/MT5/X11. Их владельческая метка проверяется до запуска.

Резервируйте приватно runtime.env, installation.json, нужный source bundle и Docker volumes.
Хеш администратора и история находятся в data volume. Сам каталог CLI не является полной
резервной копией счёта или базы. `stop` сохраняет тома; команды удаления данных в CLI нет.
Не добавляйте эти файлы в публичный репозиторий или лог обращения в поддержку.

Для CI предусмотрен `init --from-stdin`: JSON с ключами `admin_user`, `admin_password`,
`mt5_server`, `mt5_login`, `mt5_password`, при необходимости `telegram_api_id` и
`telegram_api_hash`. Передавайте его через защищённый stdin, не через shell-аргументы.
`password --stdin` аналогично читает один новый пароль. Установщик поддерживает `--no-path`
для изолированных тестов без изменения пользовательского PATH.

## Проверки разработчика

```sh
python3 -m unittest discover -s cli/tests -v
sh -n install.sh
```

GitHub Actions workflow `CLI portability` запускает unit/offline-installer проверки на
Linux, Windows и macOS с Python 3.10/3.12. Он не поднимает брокера и не выполняет ордеров.
Отдельный backend regression проверяет реальную смену пароля в ASGI-приложении, старые
cookie/Basic и WebSocket. Наличие workflow ещё не означает, что удалённый CI уже прошёл.


## Порты и диагностика

Новые установки выбирают первый свободный loopback-порт из диапазона **19471–19570**.
Проверка выполняется на Docker-хосте (для SSH — на сервере). `init --port 20471`
фиксирует конкретный порт и откажет, если он уже занят. Между проверкой и стартом порт
может занять другой процесс: используйте `doctor` перед запуском. Уже настроенные
установки сохраняют свой порт; ручной Compose остаётся совместим с портом 8000.

```sh
lvct doctor --json
lvct health
lvct health --watch --interval 10
lvct errors --since 2h
lvct logs --level critical --since 1d
lvct logs --service mt5-sidecar --level error --contains IPC
```

`health` отличает живые контейнеры от готовности MT5, Telegram и AI. `errors` группирует
сбои и предлагает следующий шаг; автоматического исправления торговых действий нет.
Неожиданные критичные ошибки CLI и обычные сбои команд пишутся в приватный ограниченный
`logs/cli.jsonl`. Исходные runtime-логи не удаляются CLI. Просмотр `logs -f` и `health
--watch` длится до Ctrl+C.

## Обновление и откат

```sh
lvct update --check
# В согласованное время обслуживания, после проверки позиций:
lvct stop
lvct update --apply
lvct doctor
lvct start
# При прерванном обновлении, пока сервисы остановлены:
lvct update --rollback
```

`update` без флагов только проверяет публичный GitHub. `--apply` отказывает, пока
работают сервисы. После сборки он готовит остановленные контейнеры, сохраняет старые
образы, CLI и source для отката; не запускает их автоматически и не меняет env/тома.
Первый Wine build может занять больше 40 минут; не обрывайте его обычным таймаутом.
Для проверенного локального исходника есть `update --apply --source PATH`.
Откат возвращает код и образы, но не отменяет миграцию базы, выполненную после запуска
новой версии. Перед таким запуском нужна отдельная резервная копия томов.

## Отчёт в поддержку

```sh
lvct report --note "Коротко опишите проблему"
# Прочитайте сохранённый JSON, затем отправьте его по напечатанному пути:
lvct report --send --file PATH
```

Сначала создаётся локальный файл. Отправка выполняется только явно: на официальный
сервер попадают обезличенные последние ошибки и состояние компонентов. Владелец
получает уведомления по Telegram и почте; принятие сервером не означает доставку
уведомлений. `--contact EMAIL` добавляет адрес для ответа по желанию. Полные env,
база, брокерские файлы и история сделок не отправляются. Проверьте JSON: маскирование
произвольного текста не гарантирует удаления всех чувствительных сведений.
Подробности и срок хранения 14 дней — в [Support](SUPPORT.md).

Для автоматизации читайте [инструкции агентам](CLI-AGENTS.md): коды возврата,
длительные команды, правила обслуживания и разрешения на отправку отчёта.
